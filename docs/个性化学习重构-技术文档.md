### 1.3 核心流程

Agent 主链路（`agent/graph.py:70-148`）为扁平单图，13 节点：

```
START → build_context → classify → [route_by_intent]
  ├─ query_rag    → [route_after_rag] → finalize → END   # 简单问答
  ├─ agentic_rag  → [route_after_rag] → (同上)            # 复杂问答（LLM 自主 ReAct）
  ├─ get_mastery  → query_rag → (同上)                    # 练习/复习前置
  ├─ diagnose     → finalize → END                        # 学情诊断
  └─ human_review → [route_after_review] → get_mastery / finalize   # 人工审批
```

练习闭环（两套独立入口）：

- **API 路径**：`POST /agent/chat` 生成 quiz → `POST /practice/{session}/submit` 批改（`api/practice.py:100-216`）→ 触发 `update_profile`。
- **MCP 路径**：`generate_practice` / `grade_answers`（`mcp/tools/practice.py:62-188`）各自独立实现，`grade_answers` 不触发画像更新。

### 1.5 已知问题

| 类别 | 事实 | 位置 |
|---|---|---|
| **耦合过高** | `finalize_node` 单一函数承担 9 项职责、7 个 `asyncio.create_task`（guardrails、audit、写 QA、更新会话、滚动压缩、诊断落库、画像更新、L3 抽取、embedding 补全） | `agent/nodes.py:131-309` |
| **耦合过高** | 扁平单图无子图隔离，四个技能共享同一 `AgentState`（30+ 字段） | `agent/graph.py:70-148`、`agent/state.py:9-76` |
| **技术债** | 掌握度聚合 SQL 重复两处（正确率计算逻辑一致） | `agent/profile_updater.py:35-68`、`agent/skills/diagnose.py:100-142` |
| **技术债** | 批改实现重复两套（内存批量 vs DB 单题） | `agent/skills/grade_answers.py`、`mcp/tools/practice.py:133` |
| **技术债** | prompt 两套并存（`mcp/prompts/` 三模板 vs 各 skill 内联） | `mcp/prompts/*.py`、`agent/skills/*.py` |
| **技术债** | 5 处 skill 各自实例化 `AsyncOpenAI`，无统一客户端/重试 | `classify_intent.py`、`generate_quiz.py`、`diagnose.py`、`review_plan.py`、`generator.py` |
| **数据流断裂** | 问答主链路（`query_rag`/`agentic_rag`）不回流掌握度，作答信号丢失 | `agent/graph.py:110-123` |
| **数据流断裂** | MCP 出题传空掌握度；MCP 批改不触发画像更新 | `mcp/tools/practice.py:88`、`mcp/tools/practice.py:154-162` |
| **数据模型缺口** | 掌握度为静态正确率，无置信度、无遗忘、无 BKT 状态 | `models/user_profile.py:36-38` |
| **数据模型缺口** | 作答记录无结构化错因，错因仅存于 `memory_facts`（LLM 异步抽取） | `models/practice_record.py`、`agent/memory/extractor.py` |
| **持久化风险** | 后台任务用 `asyncio.create_task`，进程重启即丢失、无重试 | `agent/nodes.py:234-285` |
| **持久化风险** | `AsyncPostgresSaver` 模块级单例持单条连接，无重连逻辑 | `agent/graph.py:51-67` |

## 二、重构方向

### 2.1 要解决的核心问题

1. **个性化退化**：`mastery_level` 为正确率，导致"个性化"仅体现为向 LLM 注入一段 `weak_kps` 文本，未改变内容深度、难度或推荐。
2. **闭环断裂**：学情诊断 → 内容推荐 → 练习反馈 → 学情更新 四环中，问答不回流、练习错因不结构化、MCP 路径不出数据，四环无法闭合。
3. **四技能孤立**：问答/学情/计划/练习各自读写，无共享的单一事实源，退化为"四个孤立功能"。
4. **重复与高耦合**：批改、掌握度聚合、prompt 各存在多套实现；`finalize_node` 职责过载。

### 2.2 目标架构

```
                  ┌───────────────────────────────────┐
                  │  LearnerStore（单一事实源，图外）    │
                  │  learner_id → { skills: BKT 状态,   │
                  │                 misconceptions,     │
                  │                 theta(IRT), logs }  │
                  └─────▲─────────▲──────────▲─────────┘
               WRITE    │    READ │    READ  │ READ
         ┌──────────────┴──┐ ┌────┴─────┐ ┌──┴──────┐
         │ 问答（grade→写）  │ │ 学情（读） │ │ 计划（读）│
         │ 练习（读+写）     │ │          │ │         │
         └─────────────────┘ └──────────┘ └─────────┘
```

要点：

- 四个技能统一读写 `LearnerStore`，彼此不直接传数据。
- Store 位于图外；图 state 仅存 `learner_id` 指针，避免 checkpoint 膨胀。
- 写入口唯一：`record_attempt(learner, skill, correct, cause)`。

### 2.3 关键改进点

| 维度 | 现状 | 目标 | 方式 |
|---|---|---|---|
| **数据流** | 正确率全量重算、问答不回流 | 作答事件增量更新 BKT 状态 | 引入 `record_attempt` 统一回流入口，问答/练习/批改均走该入口 |
| **掌握度语义** | `mastery_level` = correct/total | BKT 掌握概率（含置信度、遗忘） | 新增 `bkt_state` 列，旧列保留只读（双轨兼容） |
| **职责边界** | `finalize_node` 上帝节点 | 副作用任务外移，主流程只负责收口 | 拆解 `finalize_node`，后台任务入独立 `tasks` 表 |
| **单一事实源** | 批改/聚合/prompt 各多套 | 各概念唯一实现 | 合并批改入口、收敛聚合 SQL、统一 prompt 仓库 |
| **错因结构化** | 错因靠 LLM 异步抽到 JSON | 作答事件内联归因 | `PracticeRecord` 加 `error_cause`/`source` 字段 |
| **自适应选题** | 无 IRT | 按信息量选题 | `Question` 加 IRT `a`/`b` 参数（默认占位，后续标定） |
| **内容推荐** | 只注入 `weak_kps` 文本 | 按掌握度调节解释深度与难度区间 | `generator` 按 `get_mastery(kp)` 分档 |

### 2.4 预期收益

- **闭环闭合**：作答 → 追踪状态 → 诊断/计划/练习，四环共享同一份学情。
- **数据资产沉淀**：掌握度轨迹随时间累积，构成竞品无法复制的长期数据。
- **可维护性**：消除重复实现（批改、聚合 SQL、prompt），降低改动回归面。
- **可观测**：后台任务落表后可查询、可重试，替代不可见的 `create_task`。

### 2.5 需规避的风险

| 风险 | 规避方式 |
|---|---|
| 删除重复批改破坏 MCP/API 任一路径 | 先补齐双路径测试覆盖，再合并，灰度切换 |
| BKT 状态迁移致旧正确率不可读 | 双轨兼容：新列写 BKT，旧列保留只读，脚本回填初始先验 |
| 后台任务迁队列引入新依赖 | 先复用 asyncio 任务 + 持久化任务表，不引入 Redis/Celery |
| 撤销人工审批后教师端中断 | 保留 approve 端点，仅改触发条件，前端兼容空列表 |
| BKT 参数未标定导致状态失真 | 先用默认参数双轨运行，标定后再切换，全程 feature flag 可回退 |

## 三、相关技术

### 3.1 语言与运行时

| 技术 | 角色 |
|---|---|
| Python `>=3.12` | 后端唯一语言，async 为主 |
| uv | 依赖与虚拟环境管理（`src` 布局） |
| PyTorch（CUDA 12.6） | 嵌入/重排模型的推理底座 |

### 3.2 现有技术（沿用，按角色分组）

| 技术 | 角色 | 选型理由 |
|---|---|---|
| FastAPI + Uvicorn | Web 框架 | async 原生，与 SQLAlchemy async、AsyncOpenAI 一致 |
| SQLAlchemy 2（async）+ asyncpg | ORM | 异步 + 类型友好，配合 `Mapped` 声明式模型 |
| Alembic | 迁移 | 增量 schema 变更（如新增 `bkt_state`、`error_cause` 列） |
| PostgreSQL 16 | 主库 | 递归 CTE（知识点树）、JSONB（画像）、`AsyncPostgresSaver` |
| LangGraph + checkpoint-postgres | Agent 编排与持久化 | 图工作流 + 会话 checkpoint，支持 `interrupt()` HITL |
| LangChain / LangChain-OpenAI | LLM 抽象与工具 | 与 LangGraph 生态一致 |
| instructor | 结构化输出 | 声明但当前主链路未使用（`openai` + `json_object` 手解析），为收敛点 |
| Milvus Lite + FAISS | 向量检索 | 嵌入式免独立服务，适配单实例部署 |
| rank-bm25 + bge-reranker-v2-m3 | 混合检索 + 重排 | BM25 补向量召回，RRF 融合，重排提精度 |
| BGE-M3（FlagEmbedding） | 文本嵌入 | 中英多语言、CPU 可推理 |
| RAGAS | RAG 评测 | 已有忠实度/引用评测 harness，可扩展个性化用例 |
| mcp | 工具暴露（Gateway + stdio） | 对外提供 tutor/diagnose/practice 能力 |
| pytest / ruff / mypy | 测试与质量 | `asyncio_mode=auto`、`line-length=100` |

### 3.3 引入 / 强化的关键技术方案

| 方案 | 角色 | 选型理由 |
|---|---|---|
| **BKT（贝叶斯知识追踪）** | 单技能掌握概率在线更新 | 输入(对错, 参数 p_L0/p_T/p_S/p_G) → 输出掌握概率；成熟、可解释、数据量要求低，是 Khan/Duolingo 类产品的核心引擎 |
| **IRT（2PL）** | 自适应诊断选题 + 能力估计 | Fisher 信息量选"最能缩小 θ 误差"的题，用最少题数定位掌握度；参数 a(区分度)/b(难度) 后续用历史作答 EM 标定 |
| **LearnerStore（单一事实源）** | 四技能共享的学情读写服务 | 写入口唯一（`record_attempt`），消除"问答更新了、练习没更新"的不一致 |
| **遗忘曲线 / 间隔复习** | 复习调度 | 优先级 = (1 - mastery) × 时间衰减，驱动靶向练习与复习计划 |
| **双轨兼容迁移** | 数据迁移安全网 | 新字段写入、旧字段只读，脚本回填，feature flag 回退 |
| **后台任务表（渐进引入）** | 副作用任务持久化 | 替代 `asyncio.create_task`，提供重试与可见性，不引入 Redis/Celery |
